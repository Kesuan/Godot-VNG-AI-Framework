# 0001 · V1 测试策略决策（功能/逻辑测试优先）

- 状态：已接受
- 日期：2026-09-14
- 关联计划：[docs/plans/0001-test-framework-v1.md](../plans/0001-test-framework-v1.md)

## 背景

项目目标是构建 AI Agent 驱动的 VNG 开发框架：Agent 在开发功能的同时编写测试，自主完成"开发 → 测试 → 修复"闭环，人类只提供体验级反馈。

框架评估的关键不是覆盖率数字，而是反馈信号的质量与速度：

- **机器可读**：JSON 结果、明确退出码、`file:line`、story node id、期望值 vs 实际值
- **稳定可复现**：确定性 > 覆盖率。不稳定测试会迫使 Agent"修测试、迁就测试改代码"，闭环反而恶化
- **快**：Agent 高频迭代，快反馈层必须在秒级

## 决策

### 1. V1 只做功能/逻辑测试，不做截帧视觉/表现测试

- V1 范围：逻辑单测、剧本静态校验、剧本级 E2E、事件轨迹（trace）断言。
- 截帧/像素 golden、表现语义快照推迟；待玩法与美术稳定后再评估引入。
- 原因：截帧测试平台/驱动敏感、维护成本高；玩法未稳定时误报多，会破坏 Agent 对测试信号的信任。
- 补偿：事件轨迹作为行为回归主信号；表现层回归 V1 依赖人工体验反馈。

### 2. 自研轻量测试运行器，不基于 gdUnit4 / GUT

- 差异化价值在 Agent 报告契约、进程隔离与 VNG 专用 DSL；通用 runner 的 mock 能力对 VNG 价值有限。
- 自研可完全控制 JSON schema、退出码语义与测试生命周期。

### 3. 游戏逻辑严格 core / presentation 分离

- `game/core/` 为零 Node 依赖的纯 GDScript 状态机（节点推进、条件、flag、存档模型）。
- `game/presentation/` 只订阅 core 事件做表演。
- 服务注入 + real / fake 双实现，保证核心逻辑可 headless 直接单测。

### 4. 确定性基础设施先于玩法开发落地

- `RngService`（全局种子）、`Clock`（逻辑时间可推进）、`InputHub`（输入 → Command 注入）、`EventBus`（事件日志）、`DebugSnapshot`（全量状态 JSON）。
- 源码扫描禁止裸 `randi()/randf()/Time.*` 等非确定性 API。
- 测试固定 seed 必须可完整复现。

### 5. 测试进程模型：分层隔离

- `unit` 层：单进程内批跑（低开销，< 5s 快反馈）。
- `story` 层：每测试文件独立进程（隔离 autoload 泄漏、可超时杀、可并行）。
- 父进程负责调度与结果聚合。

### 6. Agent 运行时桥（WebSocket）不在 V1

- V1 只做"测试脚本闭环"；运行时探索式调试桥留待后续版本。

### 7. 平台范围：仅 macOS

- V1 全部测试以 `--headless` 运行，无 GPU 依赖，不涉及多平台基线问题。

## 后果

- 表现层（UI 布局、立绘、动画）的回归在 V1 不会被自动发现，依赖人工体验；这是已知且接受的缺口。
- 测试结果契约（JSON schema + 退出码）成为 Agent 编程接口，后续改动需保持向后兼容。
- 若将来引入视觉测试，需另行决策：golden 环境、平台策略、更新审批流程（新开 decision 文档）。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 基于 gdUnit4 / GUT | 报告格式与生命周期受其约束，与 Agent 契约及 VNG DSL 集成成本高于自研 |
| V1 即引入像素 golden | 平台敏感、维护成本高；玩法未稳定时持续误报 |
| 表现语义快照作为 V1 目标 | 依赖 presentation 层设计定型，会拖慢核心闭环交付 |
| 全部测试单进程 | 单例/autoload 状态泄漏导致顺序依赖，flake 难排查 |
| 不做确定性设施，直接写真机测试 | 测试不可复现，Agent 无法信任信号 |
