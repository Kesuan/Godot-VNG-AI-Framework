# 0004 · 表现层测试补充（切片复盘）

- 状态：已接受
- 日期：2026-09-14
- 关联决策：[0001 · V1 测试策略](0001-testing-strategy-v1.md)、[0003 · 游戏工程结构](0003-game-project-structure.md)

## 背景

第一条可玩切片的人工体验暴露了两个自动化测试未覆盖的缺陷：

1. **点击推进无效**：剧情屏根 `Control` 默认 `mouse_filter = STOP`，吞掉鼠标事件，`_unhandled_input` 收不到点击（键盘路径正常）。
2. **通关后重进报错**：剧情屏销毁时未解除 `services.events` 订阅，事件总线调用已释放对象的 Callable，产生 `SCRIPT ERROR`。

原 V1 决策将表现层排除在自动化之外；复盘表明：**表现层"可 headless 验证的部分"（输入路径、场景生命周期、节点状态）成本低、价值高，应当纳入。**

## 决策

1. **补充表现层 headless 冒烟测试**（L2-lite）：实例化真实场景、走真实输入路径、断言语义状态（文本/可见性/选项/flag/节点）。像素级视觉测试仍不在范围（0001 的其余结论不变）。
2. **输入仿真统一走 `addons/vng_test/dsl/input_sim.gd`**：
   - `click(tree, pos)`：先推 `InputEventMouseMotion` 建立 `mouse_over`，再推按钮事件——这是复现真实 GUI 拾取（Control 拦截）的唯一可靠方式；
   - headless 下根 Window 尺寸会被引擎重置，helper 在 motion 前显式设置 1280×720；
   - `press_action(tree, "ui_accept")` 覆盖键盘路径。
   - 测试**不得**直接调用场景内部方法（如 `request_advance()`）来"模拟"输入。
3. **场景生命周期必须测试重入**（完成 → 销毁 → 重进）：事件订阅必须在 `_exit_tree` 解除；`VngEventBus` 额外对失效 Callable 自动剪除（防御，`listener_count(type, true)` 可断言原始槽位）。
4. **引擎错误归因**：父进程把子进程引擎日志中首条 `SCRIPT ERROR` 块写入 suite 失败消息，Agent 无需翻日志即可定位。
5. 测试文件新增/修改时的自检要求：修复类改动必须做"回退验证"（临时还原修复，确认用例变红），防止测试本身失效。

## 后果

- 表现层回归从"纯人工"变为"人工 + 关键路径自动化"；人工验收清单仍保留（观感、节奏、手感）。
- 冒烟测试依赖 headless 输入仿真的行为细节（见 §2），已在 helper 内封装，避免重复踩坑。
- 后续可扩展：场景语义断言库（`expect_visible/expect_text`）、验收清单与测试用例映射、可选视觉快照（L4）。

## 被否决方案

| 方案 | 否决原因 |
| --- | --- |
| 维持"表现层零自动化" | 本次两个缺陷均为可自动化捕捉的类型，纯人工代价过高 |
| 直接调用场景方法模拟输入 | 绕过 Control 拦截与输入路由，无法捕获本次问题 |
| headless 下不设窗口尺寸直接 push_input | 视口尺寸失真，GUI 拾取失效，测试形同虚设（本次踩坑记录） |
